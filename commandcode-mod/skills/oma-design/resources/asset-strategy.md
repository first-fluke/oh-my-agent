# Design Asset Provenance

Load this resource when the affected design uses imagery, brand marks, product
previews, or placeholders. The selected design supplier owns placement and
visual treatment; OMA retains the source and what the asset can truthfully show.

## Choose relevant material

1. Reuse suitable user or project assets: approved brand marks, real product
   screenshots, photography, and existing component previews.
2. Use `oma-image` for an original raster asset when generation fits the brief
   and authorized scope. State when it is a concept rather than a real product.
3. Use stock or placeholders only when permitted. Verify the actual source,
   availability, applicable attribution, and intended placement.
4. If required material is missing, label the slot and report what is needed.
   Text-only content does not need decorative images to satisfy a quota.

## Keep claims tied to evidence

- Never invent a customer relationship or endorsement from a familiar logo.
- Do not present a generated concept, stock image, or styled mockup as a
  screenshot of the user's real product. Use an actual screenshot or component
  preview when the page makes a claim about existing functionality.
- Preserve approved logo geometry and brand identity within the requested scope.
- Retain source, license/credit requirements, and generated-asset provenance with
  the deliverable. A supplier's code license does not license every stock asset.
- Do not emit guessed asset URLs. Record unavailable or unverified material.

## Verify the affected use

Inspect the rendered placement when an implementation exists. Check that
essential content remains available if the asset fails, alternative text matches
its role, and the target viewport/theme does not conceal required information.
State when only the asset plan or file was inspected.
