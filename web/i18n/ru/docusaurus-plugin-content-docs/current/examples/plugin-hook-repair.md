# Починка хуков плагина и bootstrap проекта

Починка плагина в [`2a29d3a8`](https://github.com/first-fluke/oh-my-agent/commit/2a29d3a8eb4d760e4e4000b484c9f04761c59f5c) касалась диспетчеризации хуков и поведения bootstrap. Её родитель, `82649cbd`, задаёт состояние «до» для этого сравнения.

## Механизм сбоя

[Старый манифест хуков](https://github.com/first-fluke/oh-my-agent/blob/82649cbd70fe1a1997bf149241fbcfb629510c5e/hooks/hooks.json) вызывал файлы в `${CLAUDE_PLUGIN_ROOT}/.claude/hooks/`. Эти пути зависят от сгенерированных файлов; fixture со свежим кэшем плагина оставляет их вне каталога плагина.

[Старый bootstrap](https://github.com/first-fluke/oh-my-agent/blob/82649cbd70fe1a1997bf149241fbcfb629510c5e/scripts/plugin-bootstrap.sh) также запускал скачанный установщик Bash через `sh -c`. Маркер успеха лежал в общих данных плагина, а быстрый путь проверял только этот маркер, версию CLI и наличие файла настроек проекта. Второй проект с файлом настроек мог поэтому пропустить собственную проводку.

## Починка

[Новый диспетчер](https://github.com/first-fluke/oh-my-agent/blob/2a29d3a8eb4d760e4e4000b484c9f04761c59f5c/scripts/plugin-hook.sh) вызывает установленный CLI. Если событием уже владеет совпадающий исполняемый хук проекта, хук marketplace уступает ему, чтобы событие не диспетчеризовалось дважды.

[Новый bootstrap](https://github.com/first-fluke/oh-my-agent/blob/2a29d3a8eb4d760e4e4000b484c9f04761c59f5c/scripts/plugin-bootstrap.sh):

- Запускает установщик Bash через Bash и проверяет сбои подготовки.
- Принудительно устанавливает в проект, даже если унаследована настройка глобальной установки.
- Хранит квитанцию в `.agents/state/plugin-bootstrap.version` этого проекта.
- Перед повторным использованием квитанции проверяет конфигурацию, метаданные версии, исполняемую обёртку и зарегистрированные события.
- Сохраняет диагностику неудачной установки в `.agents/state/plugin-bootstrap.last-error.log`, не записывая успешную квитанцию.

## Воспроизведите регрессионные проверки

Используйте одноразовый checkout `2a29d3a8eb4d760e4e4000b484c9f04761c59f5c`, где уже доступны Bun и зависимости разработки репозитория. Из его корня:

```bash
bun run --cwd cli test --project scripts --maxWorkers 1 \
  plugin-bootstrap.test.ts plugin-hook.test.ts plugin-install.integration.test.ts
```

Fixture покрывают разные границы:

| Fixture | Что проверяют утверждения |
|---|---|
| [Bootstrap](https://github.com/first-fluke/oh-my-agent/blob/2a29d3a8eb4d760e4e4000b484c9f04761c59f5c/scripts/plugin-bootstrap.test.ts) | Подготовку только через Bash, отдельные квитанции проектов, конфигурацию только на CUE, неполную проводку, сбои версии и сохранённую диагностику. |
| [Диспетчеризация хуков](https://github.com/first-fluke/oh-my-agent/blob/2a29d3a8eb4d760e4e4000b484c9f04761c59f5c/scripts/plugin-hook.test.ts) | Диспетчеризацию из свежего кэша, бюджеты времени обработчиков, сохранение payload, владение совпадающим хуком проекта и запасной путь, когда этого владения нет или оно недействительно. |
| [Интеграция установки](https://github.com/first-fluke/oh-my-agent/blob/2a29d3a8eb4d760e4e4000b484c9f04761c59f5c/scripts/plugin-install.integration.test.ts) | Две установки в проекты, сохранённые пользовательские настройки, одну доставку prompt/Stop через обе регистрации и повтор после неудачной проводки. |

Эти fixture создают временные каталоги и поддельные команды CLI; интеграционный fixture использует настоящий композитор хуков. Они проверяют диспетчеризацию shell и записанные эффекты без установки marketplace и вызова модели. Наборы пропускаются в Windows.

## Что ещё проверить в реальной сессии

Успешный прогон fixture не устанавливает рабочую сессию Claude Code. В фактическом целевом проекте осмотрите квитанцию и конфигурацию, выполните `oma doctor`, перезапустите сессию и проверьте соответствующее поведение prompt и Stop вместе с наблюдаемыми эффектами. Доступность CLI, учётные данные, поведение провайдера и политика хуков хоста нуждаются в собственных доказательствах.

Тот же подход «воспроизвести, исправить, проверить» для другого сбоя начинается с [отладки падающего теста](https://firstfluke.com/oh-my-agent/docs/tasks/debug-failing-tests/). [Выбор настройки](https://firstfluke.com/oh-my-agent/docs/getting-started/choose-setup/) объясняет, когда нужен runtime проекта.
