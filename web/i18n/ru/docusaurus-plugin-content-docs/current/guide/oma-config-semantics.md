## Обзор

Конфигурация выбирается из ближайшего каталога `.agents/`, найденного при подъёме от текущего рабочего каталога:

- **Общая**: `.agents/oma-config.cue` или `.agents/oma-config.yaml`, если CUE отсутствует или не может быть вычислен.
- **Локальная**: `.agents/oma-config.local.cue` или `.agents/oma-config.local.yaml` (один файл накладывается на общую конфигурацию; этот файл следует держать приватным).

При обычном runtime-поиске OMA не объединяет файл проекта с `~/.agents/oma-config.*`. Глобальная установка читает файл HOME, потому что её корень установки — HOME; команда проекта читает ближайший слой проекта. `auto_update_cli` — намеренное исключение: при проверке обновлений сначала читается конфигурация проекта, затем конфигурация HOME, а затем применяется значение по умолчанию `true`. Полная модель описана в [справочнике конфигурации](/docs/guide/configuration-reference).

## Таблица приоритетов

| Ключ | Правило разрешения | Примечания |
|-----|:------------------:|-----------|
| `OMA_MODEL_PRESET` | Максимальный | Непустое значение окружения заменяет `model_preset` для этого процесса. |
| Локальный файл | Накладывается на общую конфигурацию | Обычные карты объединяются рекурсивно; массивы, скаляры и `null` заменяют общее значение. Оба формата локального файла одновременно существовать не могут. |
| Общий CUE | Предпочтительный | Если CUE отсутствует или завершается ошибкой, загрузчик пытается использовать общий YAML. Ошибка локального CUE является критической. |
| Общий YAML | Запасной | Используется, если не выбран пригодный общий файл CUE. |
| `auto_update_cli` | Сначала проект, затем HOME, затем `true` | Этот запасной вариант относится только к обновлениям и реализован в `resolveAutoUpdateCli`; это не общий глобальный слой. |

Для локального переопределения укажите в локальном файле только изменённые конечные значения. Например, выбор локальной модели можно не помещать в общую конфигурацию:

```yaml
# .agents/oma-config.local.yaml
model_preset: claude
agents:
  backend:
    model: anthropic/claude-sonnet-4-6
```

Запускайте команду из проекта, чтобы выбрать ближайший каталог `.agents/`. Некорректный локальный файл вызывает явную ошибку; перед повторной попыткой исправьте или удалите его.

## Значения по умолчанию

| Ключ | По умолчанию | Когда применяется |
|-----|--------------|------------------|
| `auto_update_cli` | `true` | Оба файла отсутствуют или ключ не задан |
| `serena.mode` | `bridge` | Оба файла отсутствуют или ключ не задан |
| `serena.auto_update` | `true` | Оба файла отсутствуют или ключ не задан |
| `telemetry` | `false` | Оба файла отсутствуют или ключ не задан |
| `language` | `en` | Оба файла отсутствуют или ключ не задан |
| `model_preset` | Требуется | Шаблон проекта содержит `auto`, а схема требует непустое значение. |
| `translation_voice` | `balanced` | Оба файла отсутствуют или ключ не задан |
| `timezone` | Часовой пояс системы | Оба файла отсутствуют или ключ не задан |

## Зачем нужен такой порядок чтения

Правило ближайшего слоя сохраняет конфигурацию проекта самодостаточной. Если нужна базовая конфигурация для пользователя, установите OMA глобально и измените `~/.agents/oma-config.yaml`; проектные установки всё равно могут определить собственный ближайший слой.

## Примечания

- `language` в `oma-config.yaml` управляет языком ответов агента. Он **не** используется для определения языка предупреждений при установке и обновлении: они используют локаль системы (`$LANG`), поскольку во время установки `oma-config.yaml` ещё не загружен.
- Приоритет `auto_update_cli` явно реализован в команде обновления. Если одновременно присутствуют проектная и глобальная установки, сначала проверяется значение проекта, затем значение HOME.
- `telemetry` (по умолчанию `false`) сопоставляется с собственной настройкой отказа каждого поставщика, которую `oma install` / `oma update` / `oma link` записывает следующим образом: Claude `DISABLE_TELEMETRY` + `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY`, Gemini/Qwen `privacy.usageStatisticsEnabled`, Codex `analytics.enabled` + `feedback.enabled`, Grok `[features] telemetry`, Antigravity (agy) `enableTelemetry` в `~/.gemini/antigravity-cli/settings.json`. Значение `telemetry: true` снова включает участие, удаляя отказ OMA для данного поставщика.
- `diagram` (движок `auto` / `archify` / `mermaid`, `explain_sidecar`, `archify.managed|channel|check_interval_min|path|quality|open`) — разреженный раздел переопределений навыка, аналогичный `video` / `image`; см. [руководство по Diagram Engine](/docs/guide/diagram-engine).
- `video.hyperframes.check_interval_min` ограничивает частоту проверки последней версии инструментальной цепочки HyperFrames и heygen-com/hyperframes для каждого запуска (`oma video compose`, `oma update`).
- `market` (`managed|channel|check_interval_min|path|python|save_dir`) настраивает всегда актуальный движок `last30days` за `oma market`; см. [руководство по исследованию рынка](/docs/guide/market-research).
- Типизированная схема runtime охватывает `providers`, `free`, `agents`, `models`, `custom_presets`, `vendors`, `session`, `docs` и разреженные разделы навыков. В поставляемых шаблонах также есть блоки, принадлежащие потребителям, например `scm`, `memory`, `serena_reaper` и `mcp`; их потребители владеют вложенными ключами. Не выводите ключ по этому списку — используйте [справочник конфигурации](/docs/guide/configuration-reference) и руководство по соответствующему блоку.
- Безопасно редактировать `oma-config.yaml` напрямую. `oma install` и `oma update` заменяют поля на уровне регулярных выражений и сохраняют пользовательские ключи, которыми они не управляют (например, пользовательские переопределения `agents:` и `session.quota_cap`).
- `oma update` дополнительно добавляет ключи верхнего уровня из поставляемого шаблона, которых нет в вашем файле, со значениями шаблона и маркером `# Added by oma update`. Уже имеющиеся ключи никогда не изменяются — существующее содержимое остаётся побайтно неизменным. Намеренно удалённые ключи появятся снова со значением шаблона; чтобы отказаться от них, задайте значение явно, а не удаляйте ключ.
