# Раскладка артефактов

OMA использует три расположения: `docs/` для поддерживаемых документов проекта, `.agents/results/` для читаемых человеком отчётов о выполнении и `.agents/state/` для координации и доказательств выполнения. Пути ниже указаны относительно корня проекта.

## Поддерживаемые документы

| Расположение | Содержимое |
|----------|---------|
| `docs/decisions/` | Предложения подходов, компромиссы и записи архитектурных решений (ADR) |
| `docs/plans/work/` | Планы работы, прогресс, журналы решений и трекер технического долга |
| `docs/plans/contracts/` | Принятые API-контракты |
| `DESIGN.md` | Дизайн-система UI: типографика, цвет, интервалы, motion и компоненты |

В документах решений используйте поле `Status` со значениями `draft`, `accepted` или `superseded`. Сохраняйте заменённое решение и ссылайтесь на замену, чтобы его обоснование оставалось доступным. В OMA `design` означает дизайн UI; технические предложения и ADR находятся вместе в `docs/decisions/`.

Используйте индекс документов проекта, например `docs/README.md`, чтобы ссылаться на поддерживаемые документы. Миграция артефактов переносит существующие файлы; она не создаёт индекс и не меняет статус документа.

## Отчёты о выполнении и состояние runtime

| Расположение | Содержимое |
|----------|---------|
| `.agents/results/result-*.md` | Читаемые человеком отчёты о результатах агентов и рабочих процессов |
| `.agents/results/architecture/` | Архитектурный анализ и рекомендации |
| `.agents/results/bugs/` | Отчёты об ошибках |
| `.agents/results/refactor/` | Планы и отчёты рефакторинга |
| `.agents/results/security/` | Отчёты сканирования безопасности |
| `.agents/results/market/` | Брифы исследования рынка |
| `.agents/results/recap/` | Сводки работы |
| `.agents/results/explain/` | HTML-объяснения |
| `.agents/results/api-contracts/` | Черновики API-контрактов |
| `.agents/results/plan-{sessionId}.json` | Текущий план задач |
| `.agents/state/memories/` | Сводки сессий, доски задач, прогресс, уроки и записи экспериментов |
| Runtime `agent-runs/` | Структурированные квитанции, claim и доказательства проверки |
| Runtime `agent-plans/` | Замороженные планы выполнения |

Подкаталоги отчётов остаются раздельными по областям. Читаемые человеком отчёты дополняют структурированные доказательства; сами по себе они не устанавливают проверенное завершение. См. [Результаты и возобновление](../agent-results-and-resume/).

Текущие квитанции и замороженные планы находятся в каталоге состояния проекта активного профиля. Старые проекты могут хранить их в `.agents/state/`. Их хранение и привязки проверки эта миграция не меняет.

## Перенесите поддерживаемый документ

Когда артефакт выполнения становится справочником проекта, переместите его в соответствующее поддерживаемое расположение. Например, перенесите принятый контракт из `.agents/results/api-contracts/` в `docs/plans/contracts/` или превратите архитектурную рекомендацию в запись решения в `docs/decisions/`. Оставьте ссылку на старом месте и обновите индекс документов.

Если структурированные доказательства выполнения записывают исходный файл или его хеш, оставьте этот файл нетронутым и создайте поддерживаемую версию отдельно. Ссылайтесь на поддерживаемый документ из индекса проекта.

Install, update и link по умолчанию игнорируют в Git `.agents/results/`, `.agents/state/` и `docs/plans/`. `docs/decisions/` вне этого игнорирования по умолчанию. Просмотрите `.gitignore` проекта, когда принимаете контракт или план работы, которые команда должна версионировать.

## Перенесите существующий проект {#migrate-an-existing-project}

Сначала посмотрите миграцию:

```bash
oma docs migrate --dry-run
```

Для структурированного вывода добавьте `--json`. Примените ту же миграцию явно, когда будете готовы:

```bash
oma docs migrate --dry-run --json
oma docs migrate
```

`oma install` и `oma update` тоже запускают эту миграцию. Она собирает такие устаревшие расположения:

<!-- oma-docs:ignore-start -->
| Устаревшее расположение | Назначение |
|-----------------|-------------|
| `docs/design-docs/` | `docs/decisions/` |
| `docs/plans/designs/` | `docs/decisions/` |
| `.agents/results/architecture/adr-*.md` и их авторские sidecar диаграмм | `docs/decisions/` |
| `.agents/state/memories/result-*.md` | `.agents/results/` |
| `.serena/memories/result-*.md` | `.agents/results/` |
<!-- oma-docs:ignore-end -->

Документы решений сохраняют структуру подкаталогов. Устаревшие архитектурные ADR переносятся вместе с авторскими sidecar `.archify.json` и `.archify.html`. Ревью, рекомендации и журналы проверки конкретного запуска остаются в каталоге результатов. Миграция результатов охватывает файлы `result-*.md` верхнего уровня в двух каталогах памяти; остальные файлы памяти остаются на месте.

Миграция сохраняет существующие файлы назначения. Если другой файл имеет то же имя, она добавляет суффикс источника, например `001-cache--from-plan-designs.md`, и сообщает выбранный путь. Если и это имя занято, добавляется стабильный хеш содержимого. Повторный запуск миграции не создаёт дубликаты и не переименовывает уже перенесённые файлы.

Она обновляет поддерживаемые Markdown-ссылки и ссылки на пути в перемещённых документах, Markdown-заметках координации, `docs/**/*.md` и корневых файлах `README*.md` и `AGENTS.md`. Просмотрите эти изменения вместе с отчётом миграции и Git diff. Структурированные доказательства runtime и файлы UI `DESIGN.md` исключены из переписывания ссылок. Существующие блоки `oma-docs:ignore-start` / `oma-docs:ignore-end` сохраняют примеры устаревших путей.

Просмотрите отчёт на отложенные файлы. Отчёт о результате, на который ссылаются структурированные доказательства выполнения, остаётся на исходном пути, чтобы записанные квитанция и хеш оставались действительными. Квитанции, claim, замороженные планы выполнения и другие доказательства runtime остаются на месте. Миграция не продвигает черновики контрактов, не принимает решения и не меняет дизайн-систему UI.
