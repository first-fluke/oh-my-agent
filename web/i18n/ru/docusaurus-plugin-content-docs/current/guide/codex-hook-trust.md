# Руководство: доверие к Codex hooks

При установке oh-my-agent в проект он записывает конфигурацию hook в формате вендора, включая `.codex/hooks.json` для Codex CLI. В отличие от Claude Code, Codex не запускает эти hooks автоматически. Он защищает каждый неуправляемый командный hook механизмом Trust-On-First-Use (TOFU): hook запускается только после однократной проверки и включения.

Это механизм безопасности на стороне Codex, а не ограничение oh-my-agent. В этом руководстве описаны необходимый однократный шаг, поведение при обновлении oh-my-agent и действия, которые он выполняет автоматически.

---

## Однократный шаг: проверьте hooks в Codex

После того как `oma` (install), `oma link` или `oma update` записывает `.codex/hooks.json` в проект, который Codex ещё не видел (при глобальной установке — `~/.codex/hooks.json`), hooks пока **не** запускаются. Откройте Codex и один раз проверьте их:

1. Откройте проект в Codex CLI.
2. Выполните `/hooks`, чтобы открыть список hooks в интерфейсе Codex.
3. Проверьте перечисленные hooks и включите их.

До этого шага hooks остаются недоверенными и молча пропускаются. Поэтому oh-my-agent печатает уведомление всякий раз, когда создаёт или изменяет `.codex/hooks.json`:

```text
⚠ Codex hooks installed/updated — run codex and use /hooks to trust them (untrusted hooks do not run).
```

Перед открытием Codex проверьте созданный файл:

```bash
test -s .codex/hooks.json && echo "Codex hooks are installed"
oma link codex
```

Ожидаемый результат — уведомление об установке или обновлении, после которого hooks появляются в списке `/hooks` Codex. `oma link codex` синхронизирует созданный файл; эта команда не заменяет однократное решение о доверии.

**Примечание:** `--dangerously-bypass-hook-trust` здесь не помогает. Предупреждение этой опции («Enabled hooks may run without review») означает, что она обходит проверку только для уже включённых hooks — hook, который ещё ни разу не проверяли, она не запустит. Browser `/hooks` — единственный способ впервые включить hook.

Внутри Codex сохраняет решение в `~/.codex/config.toml`, в записи `[hooks.state]`. Ключ записи составляется из пути к файлу hooks, события, блока и hook; запись содержит флаг `enabled` и `trusted_hash` строки команды.

## Что происходит при обновлениях

После того как вы доверили hooks, повторять этот шаг после каждого обновления не нужно:

- **Повторный `oma link` или `oma update` сохраняет доверие**, пока строки команд hooks не изменились. Codex сравнивает сохранённый hash с текущей командой; совпадение оставляет hook доверенным.
- **Если будущая версия oh-my-agent изменит строку команды hook**, hash перестанет совпадать, и hook молча вернётся в состояние недоверенного. Вы снова увидите уведомление установщика и должны будете повторно доверить hook через `/hooks`.

Проверка требуется только при первом запуске и после выпуска, который действительно изменил команду hook.

---

## Что oh-my-agent автоматизирует

Когда oh-my-agent сам запускает дочерний процесс Codex — например, cross-vendor agent через `oma agent spawn` — он автоматически передаёт `--dangerously-bypass-hook-trust`. Благодаря этому собственные проверенные hooks работают после обновлений без ручного повторного доверия.

Этот флаг применяется **только** к процессам Codex, которые запускает oh-my-agent. Он никогда не записывается в `~/.codex/config.toml` или конфигурацию проекта, поэтому не влияет на сессии Codex, которые запускаете вы.

---

## Flag `[features] hooks` не требуется

Старые выпуски oh-my-agent записывали `[features] codex_hooks = true` в конфигурацию Codex. В Codex 0.124 этот флаг переименован в `hooks`, а hooks стали стабильной функцией, включённой по умолчанию, поэтому флаг не нужен. oh-my-agent не записывает ни один из этих ключей и удаляет устаревшие флаги `codex_hooks` и `child_agents_md` из таблицы `[features]`, если обнаруживает их.

## Итог

| Ситуация | Действие |
|:----------|:------------|
| Первая установка / первый `.codex/hooks.json` в проекте | Откройте Codex, выполните `/hooks` и один раз включите hooks |
| `oma update` без изменения команд hooks | Ничего — доверие сохраняется |
| `oma update` изменил команду hook | Снова выполните `/hooks`, чтобы повторно доверить hook (установщик печатает уведомление) |
| Subprocess Codex, запущенный oh-my-agent | Ничего — bypass применяется автоматически |
