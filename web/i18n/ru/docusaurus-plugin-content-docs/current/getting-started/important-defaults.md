# Важные значения по умолчанию

Эти значения по умолчанию относятся к установленному runtime OMA. Загрузка одного навыка через `skills use` даёт инструкции и не настраивает хуки проекта, провайдеров и сервисы. Начните с раздела [Выбор настройки](./choose-setup.md), чтобы выбрать этот путь задачи или установку runtime.

Значения по умолчанию подобраны так, чтобы первый проект был пригоден к работе, а принадлежащая пользователю конфигурация оставалась стабильной. Они разрешаются во время выполнения, поэтому отсутствующий ключ может вести себя иначе, чем явно заданное пустое значение. Начните с этой страницы, если harness работает, но результат отличается от ожидаемого.

## Значения, влияющие на первый запуск

| Область | По умолчанию | Следствие | Переопределение |
|---|---|---|---|
| Язык ответов | Сохранённый язык, иначе системный язык; запасной вариант `en` | Установка определяет язык без запроса. Региональные локали сопоставляются с поддерживаемым базовым языком, например `ko_KR.UTF-8` → `ko`; неподдерживаемые локали используют `en`. Язык prompt пользователя имеет приоритет над этой настройкой. | `language` в `.agents/oma-config.yaml` или `.cue` |
| Маршрутизация моделей ([пресет моделей](./glossary.md#model-preset)) | `auto` | Используется нативная конфигурация агента текущего runtime. Неизвестные runtime переходят к `agents.default.cli`, если он задан. | `model_preset`, `agents.default.cli` или `agents.<id>` |
| Содержимое навыков ([пресет навыков](./glossary.md#skill-preset)) | Интерактивный выбор; `all` для автоматической настройки, если не задан `--preset` | Пресет выбирает навыки. Общие файлы, все определения рабочих процессов и агентов, хуки и настройка провайдеров остаются частью установки runtime; остальные уже существующие навыки сохраняются. | `oma install --preset <name>`; см. [ограничения пресетов](./installation.md#presets) |
| Интеллектуальный поиск по коду ([провайдер возможности](./glossary.md#capability-provider)) | `serena` | Новая установка пытается установить Serena и подключает её конфигурацию MCP. | `providers.code_intelligence: gortex` или `serena` |
| Защита поиска по коду | `block` | Пока настроен провайдер интеллектуального поиска по коду, хук PreToolUse запрещает нативные `Grep`/`Glob` и рекурсивный shell-поиск (`rg`, `grep -r`, `find -name`) и направляет агента к инструментам провайдера. Поиск, ограниченный подтверждёнными исключениями или путями вне проекта, разрешён. Хук не сообщает об обходе для исходного кода проекта. | `providers.code_intelligence_guard: off` |
| Семантическая память | `agentmemory` | Установка и обновление повторно используют рабочую конечную точку AgentMemory либо устанавливают и запускают управляемый локальный сервис, затем проверяют готовность перед успешным завершением. Явные пользовательские конечные точки проверяются без замены. | `providers.semantic_memory: honcho` или `none`; `OMA_NO_AGENTMEMORY=1` пропускает настройку AgentMemory. |
| Веб-поиск | `native` | Если провайдер не выбран, поиск использует нативный веб-канал runtime. | `providers.web` |
| Провайдер документации | `context7` | Когда навык запрашивает документацию, поиск выполняется через Context7. | `providers.docs` |
| Телеметрия | отключена | При выполнении link OMA записывает настройки отказа от телеметрии вендора. | `telemetry: true` |
| Автообновление CLI | включено | CLI проверяет обновления, если эта возможность не отключена. | `auto_update_cli: false` |
| Формат даты | `ISO` | Если проект не задаёт формат, даты используют стиль ISO. | `date_format: US` или `EU` |
| Часовой пояс | системный часовой пояс | Время расписаний и отчётов следует host, если `timezone` не задан. | `timezone: Australia/Sydney` (или другое имя IANA) |
| Транспорт Serena | `bridge` | Сессии используют один сервер Serena на проект; недоступный bridge переключается на stdio текущей сессии. | `serena.mode: stdio` |
| Автообновление Serena | включено | `oma update` при возможности обновляет локальный инструмент Serena. | `serena.auto_update: false` |
| Browser DevTools MCP | не задан | Существующие browser-записи сохраняются; новая интерактивная установка предлагает `aside`. | `mcp.devtools_browsers: [aside]`, `[chrome]`, `[firefox]` или `[]` |
| Serena Reaper | путь расписания отключён | `serena_reaper.enabled: false` оставляет периодическую очистку выключенной. Интерактивная `oma serena reap` всё равно запускается. | `serena_reaper.enabled: true` и `oma serena reaper enable` |

Имена провайдеров и значения по умолчанию поступают из загрузчика runtime и prompt установщика. Файл конфигурации, созданный установщиком, содержит комментарии к доступным разделам; используйте их как схему для конкретной версии.

## Приоритет конфигурации

OMA загружает глобальные значения по умолчанию из `$OMA_HOME/.agents/` (по умолчанию `~/.oma/.agents/`), затем накладывает общую конфигурацию ближайшего проектного `.agents/` и его локальный файл. Разные корневые каталоги проектов-предков не сливаются. В любой области предпочтителен `oma-config.cue`, а YAML служит запасным вариантом; оставляйте только один локальный overlay (`oma-config.local.cue` или `.yaml`). `OMA_MODEL_PRESET` переопределяет `model_preset` после загрузки файлов. Недействительная локальная конфигурация останавливает загрузку.

До обычного порядка для фиксированного preset действуют два особых правила маршрутизации моделей:

- При `model_preset: auto` используется нативная конфигурация агента и модели текущего runtime. Явные переопределения `agents.<id>` сохраняют приоритет; неизвестный runtime может использовать `agents.default.cli`.
- При `model_preset: free` (или любом другом LLM-провайдере `providers.<name>`) дочерние spawn используют этот шлюз. `providers.free.default_model` выбирает модель шлюза и заменяет pin моделей агентов; если значение опущено, используется `FREELLM_MODEL` или запасной вариант провайдера `auto`.

Для фиксированного или пользовательского preset эффективный порядок таков:

1. Явное переопределение `agents.<id>`.
2. Запись соответствующего `model_preset`, встроенная или из `custom_presets`.
3. Запись `orchestrator` этого preset, если для роли нет отдельной записи.
4. `agents.default.cli` как запасной вендор, когда предыдущие уровни не разрешили план.

Preset `free` задаёт значения по умолчанию для всех трёх настроек provider: `base_url` равен `http://127.0.0.1:31415/v1`, `api_key_env` — `FREELLM_API_KEY` (совместимый псевдоним `FREELLMAPI_API_KEY` также принимается), а `model` — `auto`. В выбранной переменной окружения всё равно должен находиться рабочий API key; запасного вендора нет. Если значения должны оставаться локальными для машины, задайте их в `oma-config.local.yaml`, либо используйте `FREELLM_BASE_URL` и `FREELLM_MODEL` для переопределения на уровне процесса.

## Значения с неожиданными последствиями

Отсутствующий ключ `mcp.devtools_browsers` означает «оставить текущие browser-записи без изменений». Явный пустой список удаляет browser-записи при синхронизации. Процессы browser MCP запускаются для каждой сессии агента, поэтому включайте их только для задач, управляющих browser.

Режим Serena `bridge` по умолчанию уменьшает число дублирующихся процессов language server, когда несколько агентов работают в одном проекте. `stdio` — вариант восстановления, если локальный bridge не запускается или нужна строгая изоляция процессов. Serena самостоятельно восстанавливает дочерние language server при следующем вызове инструмента; memory reaper отдельный и для обычной работы не требуется.

Телеметрия по умолчанию отключена. Установка `telemetry: true` удаляет записи отказа OMA от телеметрии вендора при следующем link/update и может снова включить функции вендора, зависящие от телеметрии. Эта настройка управляет изменениями интеграции вендора и не меняет файлы стоимости сессии, которые OMA ведёт для собственного учёта.

## Пути восстановления

| Симптом | Что проверить сначала | Восстановление |
|---|---|---|
| Файлы вендора устарели | `oma doctor` и `oma link --dry-run` | После изменения `.agents/` выполните `oma link <vendor>`; SSOT должен оставаться источником. |
| Модель не принимается | `oma doctor --profile` | Переключитесь на `auto`, используйте встроенный preset или задайте slug модели в `models:`. |
| Инструменты Serena завершаются по таймауту | `oma doctor` и раздел провайдера | Попробуйте `serena.mode: stdio`; если причина в памяти, сначала выполните `oma serena reap --dry-run`. |
| [Постоянный рабочий процесс](./glossary.md#persistent-workflow) не останавливается | `.agents/state/*-state.json` | Скажите `workflow done`; проверяйте state-файл, только если рабочий процесс не очистил его. |
| Планировщик reaper ничего не делает | Раздел Serena Reaper в `oma doctor` | Задайте `serena_reaper.enabled: true`, затем выполните `oma serena reaper enable`. |
| Локальная конфигурация ломает запуск | Путь ошибки `oma doctor` | Исправьте или удалите local overlay; не создавайте одновременно overlay `.cue` и `.yaml`. |

Продолжите с разделом [Установка](./installation.md), [Модели агентов](../guide/per-agent-models.md) или [Семантика конфигурации OMA](../guide/oma-config-semantics.md). Проблемы, не перечисленные здесь, описаны в разделе [Устранение неполадок](../guide/troubleshooting.md).
