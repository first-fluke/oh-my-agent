# Выбор настройки

Выберите точку входа для задачи, которую нужно выполнить.

| Потребность | Точка входа | Что настраивается |
|---|---|---|
| Одна сфокусированная задача в текущем агенте | [Загрузить один навык](#load-one-skill) | Инструкции и вспомогательные файлы во временном каталоге |
| Хуки проекта, специализированные агенты и рабочие процессы | [Установить пресет навыков](#install-a-skill-preset) | Интеграция runtime OMA с выбранными навыками |
| Установка из marketplace Claude Code | [Установить плагин](#install-the-claude-code-plugin) | Плагин OMA и bootstrap проекта |
| Установка пакета Copilot CLI, Kiro, Qwen Code, Hermes или Codex | [Пакет Agent Plugins](../guide/vendor-capabilities.md#agent-plugins-package) | Навыки и MCP-серверы для каждого хоста; Copilot также получает агентов, команды, правила и хук bootstrap |

## Загрузить один навык {#load-one-skill}

Попросите coding agent выполнить команду для вашей задачи и прочитать возвращённые инструкции. `skills use` печатает инструкции и путь к их каталогу поддержки. Он не запускает другого агента и не запускает установщик OMA.

| Задача | Команда | Первый запрос |
|---|---|---|
| Дизайн админ-интерфейса или ревью существующего UI | `bunx skills use first-fluke/oh-my-agent@oma-design` | Review our admin page's hierarchy, table density, and empty states. |
| Воспроизводимая ошибка | `bunx skills use first-fluke/oh-my-agent@oma-debug` | Reproduce this failure, fix its cause, and run the relevant check. |
| Архитектурное решение | `bunx skills use first-fluke/oh-my-agent@oma-architecture` | Compare keeping this job in the API with moving it to a worker. |

Выбранный каталог включает общие ссылки на инструкции. Зависимости вне этого каталога остаются явными: другой предметный навык, правила проекта, операции CLI, инструменты браузера или внешний движок всё ещё могут понадобиться. Прочитайте зависимости выбранного навыка для запрошенной операции. Устанавливайте runtime, когда задаче нужны его хуки или управляемое выполнение.

Для работы с дизайном `oma-design` выбирает Interface Design для направления админки и интерфейса продукта, Taste для прочего веб-арт-направления и Impeccable для критики, аудита и доводки существующего UI. Стек проекта и `DESIGN.md` остаются контрактами реализации и дизайна.

## Установить пресет навыков {#install-a-skill-preset}

Установите CLI один раз, затем выберите навыки проекта:

```bash
bun install --global oh-my-agent
oma install --preset frontend --yes
oma doctor
```

Существующая установка CLI может начаться со второй команды. Имена пресетов и параметры провайдеров смотрите в `oma install --help`. [Bootstrap-установщик](https://firstfluke.com/oh-my-agent/docs/getting-started/installation/#method-1-one-liner-install) также готовит зависимости runtime до интерактивной настройки.

| Пресет | Первая задача | Примеры применимых рабочих процессов |
|---|---|---|
| `frontend` | Спланировать страницу настроек, затем реализовать её форму | `/plan`, `/design`, `/review`, `/debug` |
| `backend` | Спланировать аутентифицированный API endpoint | `/plan`, `/architecture`, `/review`, `/debug` |
| `research` | Найти статьи и сравнить их доказательства | Попросить поиск литературы с цитатами |
| `all` | Скоординировать функцию между UI, API и данными | `/orchestrate`, `/work`, `/ultrawork`, `/ralph` |

[Именованные пресеты](https://firstfluke.com/oh-my-agent/docs/getting-started/installation/#presets) принимает `--preset`. Неизвестное имя, пустое значение или `custom` отклоняются до установки. Чтобы выбрать навыки по отдельности, запустите `oma install` интерактивно и выберите Custom. Без `--preset` автоматическая настройка `--yes`/CI выбирает `all`.

Пресет frontend выбирает восемь навыков. Пресеты выбирают содержимое навыков; установщик всё равно настраивает общие файлы, все определения рабочих процессов и агентов, хуки и провайдеров. Некоторым рабочим процессам нужны навыки вне предметного пресета. Перед их использованием проверьте [зависимости рабочих процессов](https://firstfluke.com/oh-my-agent/docs/getting-started/installation/#workflows-that-need-skills-outside-a-preset) или выберите `all` для каждого рабочего процесса. Меньший пресет на существующей установке не удаляет другие навыки.

Выбор провайдеров не зависит от пресетов. Например, добавьте `--semantic-memory none`, если проекту не нужен сервис семантической памяти. Остальные файлы и интеграции, которые настраивает runtime, описаны в [эффектах установки](https://firstfluke.com/oh-my-agent/docs/getting-started/installation/#what-the-installer-also-does-by-default).

Сводка установки перечисляет выбранные навыки и проверяет присутствующие манифесты навыков, включая сохранённые. Она сообщает статические ссылки рабочих процессов и агентов, включая условные ветки, как ссылки на манифесты навыков. Запустите `oma doctor`, чтобы починить отсутствующие или нечитаемые записи, нужные для задачи. Эти проверки не проверяют содержимое ресурсов, инструменты, провайдеров, учётные данные и выполнение.

## Установить плагин Claude Code {#install-the-claude-code-plugin}

Выполните эти команды внутри Claude Code:

```text
/plugin marketplace add first-fluke/oh-my-agent
/plugin install oma@oh-my-agent
```

Для предметного плагина выберите `oma-frontend@oh-my-agent`, `oma-security@oh-my-agent` или `oma-research@oh-my-agent`. Полная запись `oma` сохраняет весь набор навыков. Предметные записи запускают bootstrap своего пресета.

Хук session-start плагина при необходимости готовит CLI и выполняет `oma install --yes` для текущего проекта. Этот путь выполняет настройку runtime. Квитанция успеха принадлежит этому проекту, а хуки событий плагина используют установленный CLI. Хукам плагина нужен Bash, в том числе в Windows. У bootstrap timeout 600 секунд; при сбое сообщаются шаги ручной настройки, а журнал проекта сохраняется в `.agents/state/plugin-bootstrap.last-error.log`. Квитанция используется повторно только после прохождения проверок версии CLI, конфигурации проекта и хуков. После сообщения о завершении bootstrap перезапустите сессию.

Для выбора конфигурации и зависимостей во время настройки используйте `oma install` напрямую. Автоматический bootstrap полного плагина использует пресет навыков `all`; каждый предметный плагин передаёт свой выбранный пресет. Меньший пресет сохраняет другие навыки, уже установленные в проекте.

## Проверьте результат

Для загруженного навыка убедитесь, что агент прочитал выбранные инструкции, и сообщите фактические проверки задачи. Для установки runtime выполните `oma doctor` и попробуйте первый запрос своего пресета. Предупреждения doctor о провайдере важны, когда запрошенная задача использует этот провайдер.
