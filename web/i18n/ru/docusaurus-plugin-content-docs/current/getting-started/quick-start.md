# Быстрый старт

Проверьте результат на одной сфокусированной задаче. Загрузите навык в coding agent, которым уже пользуетесь, либо установите runtime, если нужны проектные хуки, специализированные агенты и рабочие процессы. Доступные варианты и их зависимости описаны в разделе [Выбор настройки](./choose-setup.md).

## 1. Выбор настройки {#1-install}

Для read-only Git-задачи ниже попросите агента загрузить навык и прочитать его инструкции и каталог поддержки:

```bash
bunx skills use first-fluke/oh-my-agent@oma-scm
```

Переходите к задаче на шаге 3. CLI-операции этого навыка, другие навыки, правила проекта и внешние сервисы остаются отдельными зависимостями. Загрузка этого навыка не запускает установщик OMA.

### Установка runtime при необходимости

Bootstrap runtime может подготовить `bun`, `uv`, Serena, CUE и глобальную команду `oma`. Выберите AI CLI или IDE, которым уже пользуетесь; интеграции провайдеров и браузера зависят от задач, которые вы планируете запускать.

Из каталога проекта запустите bootstrap-установщик:

```bash
curl -fsSL https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.sh | bash
```

В Windows PowerShell выполните:

```powershell
irm https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.ps1 | iex
```

Настройка сохраняет существующий язык ответов или автоматически определяет системный язык. Интерактивная настройка запрашивает CLI-вендоров, [провайдеров возможностей](./glossary.md#capability-provider), [пресет моделей](./glossary.md#model-preset), [пресет навыков](./glossary.md#skill-preset) проекта и вариант стека. Для первого запуска оставьте значения по умолчанию, выберите уже используемого вендора и пресет проекта, наиболее близкий к репозиторию. Навыки каждого пресета и [рабочие процессы, которым нужны навыки вне пресета](./installation.md#workflows-that-need-skills-outside-a-preset), описаны в разделе [Пресеты](./installation.md#presets).

Если `bun` уже установлен, используйте установщик напрямую:

```bash
bunx oh-my-agent@latest
```

Bootstrap-скрипты устанавливают OMA в текущий проект. Используйте `oma install --global`, когда нужен уровень HOME; перед смешиванием проектной и глобальной установки прочитайте [Глобальную установку](../guide/global-install.md).

## 2. Проверьте результат

При временной загрузке навыка убедитесь, что агент прочитал выбранные инструкции, и проверьте саму задачу. Для установки runtime запустите проверку состояния из того же каталога проекта:

```bash
oma doctor
```

Текстовая команда печатает отчёт с разделами, например `CLI Status` и `Skills Status`, затем возвращает код завершения shell. Точные строки зависят от host, установленных в проекте:

```text
┌   🩺 oh-my-agent doctor
◇  CLI Status ...
◇  Skills Status ...
$ echo $?
0
```

`oma doctor` может сообщать о проблемах необязательных интеграций как о предупреждениях. Подготовка AgentMemory по умолчанию проверяется во время `oma install` и `oma update`; сбои установки, запуска или проверки работоспособности останавливают эти команды. Выбор `providers.semantic_memory: none` или `honcho`, а также установка `OMA_NO_AGENTMEMORY=1` пропускают эту подготовку.

Для машиночитаемого статуса `oma doctor --json` возвращает ненулевой код завершения, если отчёт содержит проблемы. Для просмотра разрешённых моделей и CLI каждой канонической роли агента используйте `oma doctor --profile`.

Если `oma` недоступна, но Bun установлен, выполните ту же проверку без глобальной команды:

```bash
bunx oh-my-agent@latest doctor
```

Если команда по-прежнему не найдена, откройте новый shell или добавьте каталог bin менеджера пакетов в `PATH`; как установить команду `oma`, показано в разделе [Установка](./installation.md#method-3-global-install). Если `oma doctor` сообщает о недопустимой конфигурации, исправьте указанное поле и запустите проверку снова. Не удаляйте `.agents/oma-config.yaml` для восстановления: это принадлежащая пользователю конфигурация, сохраняющая настройки между обновлениями.

## 3. Выполните одну небольшую задачу

Откройте существующий Git-репозиторий в своём AI-инструменте. Используйте загруженный навык `oma-scm` или копию, установленную именованным пресетом runtime. Если вы выбрали Custom, включите для этого примера `oma-scm`:

```text
Use oma-scm to inspect this repository's current branch and working tree. Do not edit, stage, commit, or contact remotes. Report staged, unstaged, and untracked changes, with the Git commands and exit statuses actually observed.
```

Сравните указанную ветку и изменения с фактическим выводом Git. Агент должен сообщить, какие команды запускались и с какими кодами завершения. Для этой read-only задачи не нужны тесты кода или сборка.

Обычный prompt не запускает рабочий процесс; там, где включён prompt hook, он добавляет рекомендательную подсказку о навыке. Маршрутизацию навыков выполняет host или выбранный рабочий процесс, поэтому произвольный prompt host не гарантирует hook или конкретный навык. Контракт выполнения всё равно должен проверить соглашения репозитория, соблюсти запрошенную read-only область и сообщить о проверке. Точные файлы и команда зависят от проекта.

Для задачи, пересекающей границы API и UI, явно выберите `/work` или `/orchestrate`. Для одной предметной области перейдите к [выполнению одного навыка](../guide/single-skill.md). Более длинные примеры находятся в [руководстве по использованию](../guide/usage.md).

## 4. Узнайте значения по умолчанию до масштабирования

Временная загрузка навыка не настраивает эти значения runtime по умолчанию. Для проектных хуков, настройки провайдеров или командных рабочих процессов используйте путь runtime в разделе [Выбор настройки](./choose-setup.md).

OMA запускается с `model_preset: auto`, Serena для code intelligence, Agent Memory для semantic memory, native web search и отключённой telemetry. Serena использует общий transport `bridge` и автоматически обновляется, если это не переопределено. Browser DevTools MCP включается явно; новая интерактивная установка сначала предлагает Aside. Последствия и ключи переопределения описаны в разделе [Важные значения по умолчанию](./important-defaults.md).

Если управляемая задача остановилась, начните с `oma agent status <session-id> [agent-id]`, затем проверьте её квитанцию в `.agents/state/agent-runs/` и внедрённый путь structured claim. Эти записи показывают run, task, workspace, exit code и статус проверки. Читаемые человеком файлы `result-*.md` и `progress-*.md` в `.agents/state/memories/` добавляют контекст, если они существуют. Повторяйте только наименьшую неудачную команду после того, как убедитесь, что run больше не активен. [Постоянный рабочий процесс](./glossary.md#persistent-workflow) остаётся активным до завершения или команды `workflow done`; восстановление по state-файлу описано в [рабочих процессах](../core-concepts/workflows.md#persistent-mode-mechanics).
