# Быстрый старт

Используйте эту страницу, чтобы выполнить одну небольшую задачу и зафиксировать конкретный результат. Вам понадобятся каталог проекта и хотя бы один поддерживаемый AI CLI или IDE. Установщик может настроить `bun`, `uv`, Serena и CUE в macOS, Linux или Windows; для первого prompt требуется выбранная интеграция host, а интеграции provider и browser необязательны.

## 1. Установка

### Самый быстрый путь — навыки в ваших агентах

```bash
npx skills add first-fluke/oh-my-agent
```

Это устанавливает пакет навыков OMA в обнаруженные runtime агентов (Claude Code, Cursor, Codex и другие). Навыки учат агента, как работать. Для шлюзов stop-hook, проверки артефактов, независимых judge и CLI `oma` установите полный harness ниже.

Установка только навыков не включает CLI `oma`, хуки, рабочие процессы и judge. Для первой задачи ниже используйте именованный установленный навык; полный harness нужен, когда требуются проверки через CLI.

### Полный harness (шлюзы, хуки, CLI)

Из каталога проекта запустите bootstrap-установщик:

```bash
curl -fsSL https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.sh | bash
```

В Windows PowerShell выполните:

```powershell
irm https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.ps1 | iex
```

Интерактивная настройка запрашивает язык ответов, CLI-вендоров, провайдеров возможностей, preset модели, preset навыков проекта и вариант стека. Для первого запуска оставьте значения по умолчанию, выберите уже используемого вендора и preset проекта, наиболее близкий к репозиторию.

Если `bun` уже установлен, используйте установщик напрямую:

```bash
bunx oh-my-agent@latest
```

Bootstrap-скрипты устанавливают OMA в текущий проект. Используйте `oma install --global`, когда нужен уровень HOME; перед смешиванием проектной и глобальной установки прочитайте [Установку](./installation.md).

## 2. Проверьте результат (только для полного harness)

Если вы установили полный harness, запустите проверку состояния из того же каталога проекта:

```bash
oma doctor
```

Текстовая команда печатает отчёт с разделами, например `CLI Status` и `Skills Status`, затем возвращает код завершения shell. Точные строки зависят от host, установленных в проекте:

```text
┌   🩺 oh-my-agent doctor
◇  CLI Status ...
◇  Skills Status ...
$ echo $?
0
```

Необязательные интеграции MCP, browser, memory или code intelligence могут появиться как предупреждения; они нужны только для задач, которые их используют. Для машиночитаемого статуса `oma doctor --json` возвращает ненулевой код завершения, если отчёт содержит проблемы. Для просмотра разрешённых моделей и CLI каждой канонической роли агента используйте `oma doctor --profile`.

Если `oma` недоступна, но Bun установлен, выполните ту же проверку без глобальной команды:

```bash
bunx oh-my-agent@latest doctor
```

Если команда по-прежнему не найдена, откройте новый shell или добавьте каталог bin менеджера пакетов в `PATH`. Если `oma doctor` сообщает о недопустимой конфигурации, исправьте указанное поле и запустите проверку снова. Не удаляйте `.agents/oma-config.yaml` для восстановления: это принадлежащая пользователю конфигурация, сохраняющая настройки между обновлениями.

Если вы установили только навыки, пропустите эту проверку CLI и перейдите к задаче с именованным навыком ниже.

## 3. Выполните одну небольшую задачу

Откройте репозиторий в настроенном AI-инструменте и запросите один именованный навык и один самостоятельный результат:

```text
Use the discovered `oma-docs` skill to check one existing link in this project's README. If it is stale, update only that link. Done when you report the inspected target, the exact verification command, and its exit status.
```

Host должен определить выбранный навык, проверить одну цель и сообщить либо о точечной правке ссылки, либо о том, что ссылка уже корректна. Включите в отчёт вывод команды и код завершения для каждой проверки, которая действительно выполнялась. Установка только навыков не добавляет `/debug`, `/ralph`, хуки или шлюзы рабочих процессов; запрос именованного навыка удерживает эту первую задачу в рамках установленных возможностей.

Если для выбранного host включён keyword hook, он может активировать подходящий workflow. Маршрутизацию навыков выполняет host или выбранный workflow, поэтому произвольный prompt host не гарантирует hook, конкретный skill или `CHARTER_CHECK`. Контракт выполнения всё равно должен проверить соглашения репозитория, ограничиться указанной областью и сообщить о проверке. Точные файлы и команда зависят от проекта.

Для задачи, пересекающей границы API и UI, явно выберите `/work` или `/orchestrate`. Для одной предметной области перейдите к [выполнению одного навыка](../guide/single-skill.md). Более длинные примеры находятся в [руководстве по использованию](../guide/usage.md).

## 4. Узнайте значения по умолчанию до масштабирования

OMA запускается с `model_preset: auto`, Serena для code intelligence, Agent Memory для semantic memory, native web search и отключённой telemetry. Serena использует общий transport `bridge` и автоматически обновляется, если это не переопределено. Browser DevTools MCP включается явно; новая интерактивная установка сначала предлагает Aside. Последствия и ключи переопределения описаны в разделе [Важные значения по умолчанию](./important-defaults.md).

Если управляемая задача остановилась, начните с `oma agent status <session-id> [agent-id]`, затем проверьте её receipt в `.agents/state/agent-runs/` и внедрённый путь structured claim. Эти записи показывают run, task, workspace, exit code и статус проверки. Читаемые человеком файлы `result-*.md` и `progress-*.md` в `.agents/state/memories/` добавляют контекст, если они существуют. Повторяйте только наименьшую неудачную команду после того, как убедитесь, что run больше не активен. Persistent workflow остаётся активным до завершения или команды `workflow done`; восстановление по state-файлу описано в [рабочих процессах](../core-concepts/workflows.md#persistent-mode-mechanics).
