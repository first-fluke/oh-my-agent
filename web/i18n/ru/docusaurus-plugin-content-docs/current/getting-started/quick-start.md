# Быстрый старт

Используйте эту страницу, чтобы выполнить одну небольшую задачу и зафиксировать конкретный результат. Вам понадобятся каталог проекта и хотя бы один поддерживаемый AI CLI или IDE. Установщик может настроить `bun`, `uv`, Serena и CUE в macOS, Linux или Windows; для первого prompt требуется выбранная интеграция host, а интеграции provider и browser необязательны.

## 1. Установка

Из каталога проекта запустите bootstrap-установщик:

```bash
curl -fsSL https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.sh | bash
```

В Windows PowerShell выполните:

```powershell
irm https://raw.githubusercontent.com/first-fluke/oh-my-agent/main/cli/install.ps1 | iex
```

Интерактивная настройка запрашивает язык ответов, CLI-вендоров, [провайдеров возможностей](./glossary.md#capability-provider), [пресет моделей](./glossary.md#model-preset), [пресет навыков](./glossary.md#skill-preset) проекта и вариант стека. Для первого запуска оставьте значения по умолчанию, выберите уже используемого вендора и пресет проекта, наиболее близкий к репозиторию. Навыки каждого пресета и [рабочие процессы, которым нужны навыки вне пресета](./installation.md#workflows-that-need-skills-outside-a-preset), описаны в разделе [Пресеты](./installation.md#presets).

Если `bun` уже установлен, используйте установщик напрямую:

```bash
bunx oh-my-agent@latest
```

Bootstrap-скрипты устанавливают OMA в текущий проект. Используйте `oma install --global`, когда нужен уровень HOME; перед смешиванием проектной и глобальной установки прочитайте [Глобальную установку](../guide/global-install.md).

## 2. Проверьте результат

Запустите проверку состояния из того же каталога проекта:

```bash
oma doctor
```

Текстовая команда печатает отчёт с разделами, например `CLI Status` и `Skills Status`, затем возвращает код завершения shell. Точные строки зависят от host, установленных в проекте:

```text
┌   🩺 oh-my-agent doctor
◇  CLI Status ...
◇  Skills Status ...
$ echo $?
0
```

`oma doctor` может сообщать о проблемах необязательных интеграций как о предупреждениях. Подготовка AgentMemory по умолчанию проверяется во время `oma install` и `oma update`; сбои установки, запуска или проверки работоспособности останавливают эти команды. Выбор `providers.semantic_memory: none` или `honcho`, а также установка `OMA_NO_AGENTMEMORY=1` пропускают эту подготовку.

Для машиночитаемого статуса `oma doctor --json` возвращает ненулевой код завершения, если отчёт содержит проблемы. Для просмотра разрешённых моделей и CLI каждой канонической роли агента используйте `oma doctor --profile`.

Если `oma` недоступна, но Bun установлен, выполните ту же проверку без глобальной команды:

```bash
bunx oh-my-agent@latest doctor
```

Если команда по-прежнему не найдена, откройте новый shell или добавьте каталог bin менеджера пакетов в `PATH`; как установить команду `oma`, показано в разделе [Установка](./installation.md#method-3-global-install). Если `oma doctor` сообщает о недопустимой конфигурации, исправьте указанное поле и запустите проверку снова. Не удаляйте `.agents/oma-config.yaml` для восстановления: это принадлежащая пользователю конфигурация, сохраняющая настройки между обновлениями.

## 3. Выполните одну небольшую задачу

Откройте репозиторий в настроенном AI-инструменте и запросите один именованный навык и один самостоятельный результат:

```text
Use the discovered `oma-docs` skill to check one existing link in this project's README. If it is stale, update only that link. Done when you report the inspected target, the exact verification command, and its exit status.
```

Host должен определить выбранный навык, проверить одну цель и сообщить либо о точечной правке ссылки, либо о том, что ссылка уже корректна. Включите в отчёт вывод команды и код завершения для каждой проверки, которая действительно выполнялась.

Если для выбранного host включён keyword hook, он может активировать подходящий workflow. Маршрутизацию навыков выполняет host или выбранный workflow, поэтому произвольный prompt host не гарантирует hook, конкретный skill или `CHARTER_CHECK`. Контракт выполнения всё равно должен проверить соглашения репозитория, ограничиться указанной областью и сообщить о проверке. Точные файлы и команда зависят от проекта.

Для задачи, пересекающей границы API и UI, явно выберите `/work` или `/orchestrate`. Для одной предметной области перейдите к [выполнению одного навыка](../guide/single-skill.md). Более длинные примеры находятся в [руководстве по использованию](../guide/usage.md).

## 4. Узнайте значения по умолчанию до масштабирования

OMA запускается с `model_preset: auto`, Serena для code intelligence, Agent Memory для semantic memory, native web search и отключённой telemetry. Serena использует общий transport `bridge` и автоматически обновляется, если это не переопределено. Browser DevTools MCP включается явно; новая интерактивная установка сначала предлагает Aside. Последствия и ключи переопределения описаны в разделе [Важные значения по умолчанию](./important-defaults.md).

Если управляемая задача остановилась, начните с `oma agent status <session-id> [agent-id]`, затем проверьте её receipt в `.agents/state/agent-runs/` и внедрённый путь structured claim. Эти записи показывают run, task, workspace, exit code и статус проверки. Читаемые человеком файлы `result-*.md` и `progress-*.md` в `.agents/state/memories/` добавляют контекст, если они существуют. Повторяйте только наименьшую неудачную команду после того, как убедитесь, что run больше не активен. [Постоянный рабочий процесс](./glossary.md#persistent-workflow) остаётся активным до завершения или команды `workflow done`; восстановление по state-файлу описано в [рабочих процессах](../core-concepts/workflows.md#persistent-mode-mechanics).
