# Спроектировать админ-интерфейс вокруг реальных задач

Используйте `oma-design`, чтобы решить, как экран админки должен помогать пользователям, до изменения кода приложения.

## Загрузите навык

Попросите coding agent выполнить эту команду и прочитать возвращённые инструкции и каталог поддержки:

```bash
bunx skills use first-fluke/oh-my-agent@oma-design
```

## Подготовьте входные данные

- Работающий экран, скриншоты или соответствующие компоненты.
- Кто пользуется экраном и какие действия нужно завершить.
- Существующие `DESIGN.md`, токены, компоненты, языки и требования к адаптивности и доступности.

## Дайте задачу

```text
Use oma-design to define the direction for our customer-support admin.
Support agents triage a ticket table, filter by status and assignee, and open
ticket details in a drawer. Keep our React stack, existing component primitives,
brand palette, and Korean/English content. Cover loading, empty, error, keyboard
focus, and narrow-screen states. Return layout decisions and a semantic-token
handoff. Update DESIGN.md if the visual system changes. Do not edit application
code or install packages.
```

## Проверьте результат

Ожидайте решения по иерархии и плотности конкретного экрана, поведение состояний, сопоставление семантических токенов и передачу в реализацию. Принятые изменения системы принадлежат каноническому `DESIGN.md` проекта.

Сверьте предложение с задачей сортировки: может ли пользователь определить следующий тикет, сменить фильтры, открыть детали и восстановиться после ошибок? Если есть отрисованный образец, проверьте фокус клавиатуры, читаемость корейского и английского текста и поведение на узком экране. Передача только документом оставляет проверку в браузере и проверку доступности невыполненными.

## Зависимости и следующий шаг

Для нового направления админки или интерфейса продукта [контракт маршрутизации](https://github.com/first-fluke/oh-my-agent/blob/82649cbd70fe1a1997bf149241fbcfb629510c5e/.agents/skills/oma-design/resources/external-design-skills.md) выбирает Interface Design. Критика, аудит и доводка существующего UI выбирают Impeccable; прочее веб-арт-направление использует Taste. Для текущей операции загружается один поставщик.

Этим внешним инструкциям могут понадобиться собственные загрузки или инструменты runtime. Существующие стек, бренд, покрытие CJK, цель WCAG и требования reduced-motion остаются ограничениями. Загрузка инструкций не отрисовывает и не проверяет UI.

Для реализации используйте фронтенд-специалиста проекта. Для хуков и рабочих процессов проекта [выберите настройку runtime](https://firstfluke.com/oh-my-agent/docs/getting-started/choose-setup/#install-a-skill-preset), которая включает `oma-design`.
