# プロジェクトハーネス進化

OMA は追跡中のエージェント実行から証拠を集め、スケジュールされたフィードバックサイクルで失敗を処理できます。スキルの自動変更は**プロジェクトで有効化するまでオフ**です。各サイクルにはモデル呼び出しの予算が有限に定められ、適用される変更は既存のスキル評価ゲートを通過しなければなりません。

自動経路が改善するのはスキル文書です。オプティマイザやメンテナ手順そのものの変更は、別途手動で呼び出す[メタ最適化](/docs/guide/skill-opt)のままです。

## プロジェクトを有効化する

プロジェクトルートで実行します。

```bash
# Example allowance: at most 300 model dispatches per scheduled cycle
oma harness evolution enable --max-dispatches 300

# Evaluate proposals without applying them
oma harness evolution enable --max-dispatches 300 --mode propose

# Choose a schedule in the operating system's local time
oma harness evolution enable --max-dispatches 300 --cron "0 3 * * *"

oma harness evolution status --json
```

既定のスケジュールは毎日ローカル時刻 03:00 で、既定のモードは `apply` です。有効化時に `--max-dispatches` は必須で、正の整数でなければなりません。例の値は呼び出しの上限であり、料金の見積もりでもサイクルが完了する保証でもありません。フィクスチャスイートが大きく、採点が繰り返されるほど呼び出しを多く消費します。

<!-- oma-docs:ignore-start -->
設定は `.agents/evolution/harness-evolution.json` に保存されます。生成された証拠、リトライ状態、サイクルのロックは `.agents/state/harness-evolution/` 配下にあります。
<!-- oma-docs:ignore-end -->

有効化すると、OMA の既存 OS スケジューラに組み込みジョブが登録されます。このジョブはフィードバックサイクルを直接呼び出します。再度有効化しても、新しいジョブを作らずにプロジェクトのジョブを更新します。

```bash
# Run one cycle now under the saved mode and budget
oma harness evolution run --json

# Stop future cycles; retain evidence and applied improvements
oma harness evolution disable
```

無効化されたプロジェクトでは、遅れて届いたスケジュール呼び出しを含め、evolution コマンド経由のモデル作業は実行されません。無効化しても、すでに適用された変更はロールバックされません。

## 自動的に起こること

1. **完了証拠を記録します。** OMA が追跡する実行は、その結果と検証証拠へのローカル参照を残します。この完了ステップは追加のモデル呼び出しを行いません。同じ実行が繰り返し完了しても、証拠が重複して作られることはありません。
2. **スケジュールに従って失敗を収集します。** サイクルは対象となる失敗実行を走査し、記録された作業契約から期待動作を導き、提案された回帰フィクスチャが保存された失敗出力を実際に拒否するかを確認します。
3. **影響を受けたスキルを最適化します。** インシデントはスキルごとにグループ化されます。各スキルは、既存の学習・検証・最終テスト・隔離・負の転移チェックの下で最適化されます。
4. **適用または報告します。** `apply` モードでは、通過した候補がプロジェクトのスキルオーバーレイになります。`propose` モードでは、サイクルは結果をインストールせずに記録します。
5. **変更を報告します。** 結果は status と既存の昇格履歴で確認します。適用された変更は次回セッションの進化通知にも反映されます。

OMA がすべてのネイティブな会話やユーザーの訂正を自動的に観測するわけではありません。入力となるのは、OMA が実際に追跡している実行証拠です。保存された出力や受け入れ契約がない実行には、手動で作成した[インシデント仕様](/docs/guide/harness-incidents)が必要になることがあります。

## 予算とリトライ

サイクルは、キャプチャ、ルーブリック起案、ルーティング、採点、スキル最適化、隣接タスク、最終評価にわたって 1 つの呼び出し上限を共有します。モデル呼び出しはディスパッチ前に上限から差し引かれます。実行層がリトライした呼び出しも計上されます。スキルにより厳しい constitution の上限があれば、それも引き続き適用されます。

上限を使い切ると評価は未完了のままとなり、該当する候補は適用できません。レポートには使用量と残作業が記録されます。プロジェクトのサイクルは同時に 1 つだけ実行されます。

フィクスチャを作成しても、そのインシデントの最適化が完了したとは見なされません。中断または失敗した最適化は未完了のまま残り、バックオフ後にフィクスチャを重複させずに再開できます。完全に評価したうえで受け入れ可能な変更がなかった結果は処理済みとして記録されるため、同じ証拠が最適化を際限なく繰り返し引き起こすことはありません。新しい証拠があれば再試行が起こり得ます。

提案モードから適用モードに切り替えると、未適用の提案が処理対象になります。適用には引き続き現時点の評価と変更されていないソース内容が必要です。古い提案が無条件の書き込み指示になることはありません。

## 永続的なスキルオーバーレイ

自動変更は、管理対象のスキル定義とは別に、プロジェクトのユーザー所有の evolution 領域に保存されます。評価とプロジェクトローカルのベンダースキルリンクは、管理対象のベースとその適用可能なオーバーレイから選ばれた有効な本文を使用します。HOME スコープのベンダーインストールがプロジェクトのオーバーレイに向け直されることはありません。プロジェクトのベンダーディレクトリに管理対象外のコピーがある場合は、自動適用の前に解消する必要があります。スキルのリソースは相対パスのまま利用できます。

オーバーレイは、評価の基準にしたベースを記録します。`oma update` の後は次のように動作します。

- ベースが変わっていなければ、オーバーレイを引き続き使用します。
- ベースが変わっていれば、オーバーレイは保持したまま競合として記録し、更新されたベースを使用します。以前の評価では、新しいベース上でオーバーレイが安全であることを保証できないためです。

最適化の実行中に編集があった場合、候補がその変更済み内容を上書きすることはありません。status はレビューが必要な競合を報告します。

## 確認と取り消し

```bash
oma harness evolution status --json
oma skill promotions --all
oma skill rollback --skill oma-docs
```

昇格記録は、候補と親のハッシュ、評価証拠、レビュー可能なパッチを保持します。最初のオーバーレイをロールバックすると管理対象のベースの使用に戻り、後続のオーバーレイをロールバックすると 1 つ前のオーバーレイに戻ります。未知の編集は保持されます。記録された候補と一致しなくなった内容を、ロールバックが破棄することはありません。

既存の手動 `oma skill optimize --apply` はそのまま利用できます。スケジュールされた進化は、オーバーレイ適用経路を明示的に選択します。

## 証拠の範囲

通過したソフトウェアテストが確認するのは、配線と評価ルールです。繰り返される自動変更が、時間とともにプロジェクトの実際の作業を改善することまでは立証しません。上限を増やしたり自動化を広げたりする前に、実際の昇格、コスト、回帰、ロールバック履歴を確認してください。このスケジュールされたフィードバックループは L5 の手順昇格を呼び出しません。
